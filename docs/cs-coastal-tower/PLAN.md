# CS Civil Security — Coastal Tower: Underhang

Plan and scope for a multi-level Plazma Burst 3 campaign built from the "Coastal Tower — Underhang" concept
sheet, packaged as PB3X mods. The sheet is the mood and the ideas, not a floor plan to copy: a Civil Security
tower on huge concrete pillars over the sea at night, with fights stacked on four tiers (water, docks,
service level, upper platform), red CS banners, floodlights, wet steel and rock channels under it.

Status: **approved; the assets are in and Phase 0 is measured** (`metrics.md`); level 01 is next.

## 2. Phase 0 — measure, don't guess

Before any geometry: a Playwright harness drives the real game with the extension loaded and writes
`docs/cs-coastal-tower/metrics.md`:

- player height (standing, crouched), hitbox width — from the character's physics bodies, checked against a
  ruler placed in the editor;
- walk / run speed, jump apex, running-jump gap, double-jump / wall-jump if any, ledge reach, safe fall height,
  swim speed and buoyancy, time underwater;
- the placed footprints of the Patrol Boat, Wraith (surfaced / dived), Viper (landed / rotor clearance), Ranger
  and Bastion; the Wraith's port and lift; the boat's boarding reach (`enter` 220 px);
- the skins (frame ids) for Civil Security troops, Noir Lime and Proxy Girl; the game's AI presets and weapons;
- the engine's terrain / foliage / weather internals (what exists, what can be extended).

Every level dimension below is then re-derived from those numbers.

## 4. What's built where

**Editor objects** (generated with `Import`, editable/saveable as ordinary maps): collision walls and ramps,
water boxes and liquids, current/damage regions, lamps, enemies/allies/teams/AI presets, guns, barrels, crates,
placed vehicles, triggers, timers, dialogue text.

**New mod code**, shipped as PB3X mods (all start off, like the rest; the fifth, `cs-skies`, is below):

| Mod | What it adds |
|---|---|
| `cs-coastal-tower` | the level set and an editor button to load each level; set-piece entities drawn in 3D (tower soffit and pillars, dock frames, cranes, dry dock, pipes, rails, CS banners, floodlight rigs, z-layered background of the tower and coast); **vehicle autopilot** for enemy boats, Vipers and CS tanks; wave director, objectives, co-op scaling, ally dialogue |
| `cs-weather-terrain` | the overhaul: storm system (rain sheets, gusts, lightning, sea spray, rolling fog banks, wet-surface response), wind-driven trees, several grass types, rocks that break and tumble, extra terrain layers — keeping the game's look |
| `cs-postfx` | night grade, light shafts under the tower, wet reflections, spray/rain on the lens, hooked into the game's own renderer; each effect switchable for performance |
| `cs-assets` | licence-safe (CC0 first) textures and sounds, embedded so nothing depends on a live CDN; every source listed in `CREDITS.md` |

The models are procedural three.js built in code, the same way the mod's vehicles are built, so they're
light, lit by the map and match the game.

### Skies (a fifth mod, `cs-skies`)

HD sky panoramas behind every level (and usable on any map and as the menu backdrop, which PB3X already
supports with its "behind the city" background mode):

- **Set:** storm night with lightning, moonlit overcast, clear starry night, dusk over the sea (the sheet's
  exterior view), fog-bank dawn, and heavy squall. Each level lists the skies that suit it; a replay picks
  one of them with a matching weather preset (rain, wind, fog, lightning rate), so the same level plays
  under different conditions.
- **Layers:** the panorama itself, a moving cloud layer drawn over it, the moon and its glow, lightning that
  lights the clouds from inside, and the sky's colour feeding the map's sun/sky light, so characters and
  vehicles are lit to match.
- **Format:** each sky is a 4096 × 2048 equirectangular WebP (tonemapped from the source HDRI; HD without
  bloating the mod), plus a small blurred copy for ambient light. The budget is about 3–5 MB a sky.
- **Loading:** the files ship in `pb3x-extension/assets/skies/`, declared as `web_accessible_resources`. The
  mods run in the page, which can't call `chrome.runtime`, so a tiny isolated-world content script writes the
  extension's base URL onto the page for them to read. Nothing is fetched from a CDN at play time.
- **Editor:** a Sky picker in the world settings (none = the game's own sky), with a preview.

## 5. How each level is verified

Build → play → screenshots from at least four angles (overview, player eye line, each tier, vehicle lanes),
plus a co-op pass with 2+ players → fix → repeat until it passes the checklist (no stuck spots, all jumps are
makeable with the measured values, vehicles fit and can leave, enemies path, frame rate holds). Screenshots are
saved to `docs/cs-coastal-tower/shots/` and shown after each level before the next one starts.

## 6. Packaging

Source in `mods/*.user.js` (same format as the launcher's `mods-builtin/`), baked into
`pb3x-extension/pb3x.js` by `node tools/bake-mods.js` (done: re-baking replaces its earlier output, and with no
mods it restores the bundle byte for byte; `--check` only verifies). The same files drop into the launcher repo.
Work lands on the branch `cs-coastal-tower`, not `main`.

## 7. Blockers

- ~~The game needs a logged-in account.~~ Solved: the harness logs in with a Plazma Burst 3 authentication file
  (the site's own "I have Plazma Burst 3 account" upload). The file is the account's password: it is never
  committed, and the logged-in browser profile lives outside the repo (`/tmp/pb3x-profile`).
- A game instance on a local PC (e.g. remote debugging on port 9335) isn't reachable from a cloud container.

## 8. The play harness (`tools/harness/`)

- `launch.js` opens the game in Chromium (`/opt/pw-browsers/chromium-1194`) as a Playwright persistent context with
  `--load-extension=pb3x-extension`, under `xvfb-run` (extensions need a headed browser).
  - The build container's proxy drops some of Chromium's connections, and the site throttles bursts of script loads.
    So every request is made from Node with retries, and static files are cached in `/tmp/pb3x-cache`.
  - `mods: [...]` switches PB3X mods on for the profile.
- `login.js` logs a profile in with an authentication file.
- `game.js` starts an offline game with a map script, the way the mod's own live preview does
  (`pb2Web.RunGame` → `pb2Multiplayer.StartOffline`).
- `mapjs.js` writes map scripts (walls, water classes, characters, guns, entities), and `rigs.js` holds the Phase 0
  rigs.
- `labkit.js` runs in the page. It presses the game's own keys, reads the character, teleports it, and runs the
  physics at a fixed step.
- `shots.js` takes screenshots from set camera spots. It can pull the camera back for overviews.
- `phase0/` holds the measurements (see `metrics.md` § 7).

    NODE_PATH=/opt/node22/lib/node_modules xvfb-run -a -s "-screen 0 1600x900x24" node <script>
